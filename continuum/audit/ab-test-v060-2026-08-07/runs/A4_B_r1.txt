2. PROJETER (binary → forces → math → conscious_sets → programs → life_game_M1C1)

- binary : le choix se réduit à un bit unique — ADRESSE_COMPLETE = 1 ou 0. Il n'existe pas
  d'état intermédiaire obligatoire ; en revanche le bit peut être re-encodé en granularité
  (rue / code postal / ville / région / pays), donc le bit brut est en réalité un curseur
  à cinq crans. Le bit originel ici : "quelle précision spatiale j'émets".
- forces : deux forces opposées. (a) Force de lisibilité/confiance : le recruteur veut savoir
  si je suis atteignable et si le trajet est tenable. (b) Force de protection : toute donnée
  émise circule de façon incontrôlable (CV transféré, déposé dans un ATS, republié sur des
  jobboards, indexé). La force (a) est saturable — elle est entièrement satisfaite dès la
  granularité "ville" ; la force (b) est monotone croissante avec la précision. Deux courbes :
  l'une plafonne vite, l'autre monte sans plafond → l'optimum est au point de saturation de (a).
- math : utilité marginale de passer de "ville" à "adresse complète" ≈ 0 (aucun recruteur
  n'expédie de courrier papier au stade candidature ; les rappels se font par mail/téléphone).
  Coût marginal > 0 et à queue lourde (usurpation, démarchage, tri par distance domicile-travail,
  inférence socio-géographique sur le quartier). E[Δutilité] < 0 de façon robuste : le signe
  ne dépend pas de l'estimation fine des probabilités, seulement de "gain plafonné, coût non nul".
- conscious_sets : l'ensemble des observateurs réels du CV n'est pas l'ensemble intentionné.
  Intentionné = {recruteur cible}. Réel = {recruteur, ATS et sous-traitants, équipe RH élargie,
  jobboards, éventuels tiers non autorisés}. Toute décision doit être évaluée contre l'ensemble
  réel, pas l'intentionné. Sur l'ensemble réel, l'adresse complète est une donnée diffusée.
- programs : règle exécutable, stable et réutilisable —
  émettre la granularité minimale suffisante pour lever la seule question opérationnelle
  ("es-tu atteignable et positionné pour ce poste ?"), et déplacer la précision restante
  vers un canal ultérieur, contractuel (promesse d'embauche / onboarding).
- life_game_M1C1 : partie itérée, pas coup unique. Le CV est envoyé N fois sur des années ;
  chaque envoi rejoue le même bit. Un coût minuscule par envoi, multiplié par N envois et
  N stockages persistants, domine un gain nul répété N fois. En jeu itéré, on optimise
  la politique, pas le coup : la politique "ville" est dominante.

6. EXÉCUTER (sandbox) → AUDITER
Sandbox : test des trois variantes sur les cas d'usage courants (candidature spontanée,
jobboard, cabinet de recrutement, secteur public, candidature internationale).
- "Rue + code postal + ville" : aucun cas où cela débloque quelque chose ; plusieurs cas où
  cela ajoute un risque ou une inférence non désirée.
- "Ville (+ pays si international)" : couvre tous les cas standards.
- "Rien du tout" : crée un doute sur la localisation et la mobilité → légère perte.

Résolution (resolve, ni recover ni kill) : distinguer CV (vitrine, diffusée) et dossier
administratif (canal fermé, obligatoire) ; l'adresse va dans le second, pas le premier.
